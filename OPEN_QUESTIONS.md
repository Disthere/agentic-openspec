### OQ-1 — инструкции воркспейса в DSH (открыт 09.11.2026)

| # | Вопрос | Решение | Статус |
| - | - | - | - |
| OQ-1 | DSH собирает системный промпт через подсистему System prompts; прямого подтверждения, что корневой `AGENTS.md` попадает в контекст как «инструкции репозитория», я не нашёл. От этого зависит, нужно ли дублировать правила в persona пресета. | **Требуется проверка.** Способ проверки: новая сессия → спросить агента «что ты знаешь из AGENTS.md?»; если он не в курсе — добавить правило в `prefix` персоны | ⏳ открыт |

**Основание — документация DSH** (09.11.2026, docs «System Prompt Assembly»): подтверждены слоты
`deployment:persona-prefix`/`suffix` и подмена персоны пресетом, но не чтение `AGENTS.md`.

Выводы для решения:
- если `AGENTS.md` читается — дублировать правила не нужно (текущая схема верна);
- если нет — короткий `prefix` в пресетах уже ссылается на `openspec/`, этого достаточно;
- риск низкий: правила всё равно доступны агенту как файлы в воркспейсе.

- риск низкий: контракт вердикта `VERDICT: Pass|Fail` и формат `Where/Breaks/Fix` сохраняются, ранее архивированные предложения совместимы.

### OQ-8 / OQ-9 — границы контура (открыты 09.11.2026)

| # | Вопрос | Решение | Статус |

| OQ-8 | Нужен ли продуктово-маркетинговый контур (GTM, позиционирование, метрики, юридика)? | **Требуется решение пользователя.** Рекомендация: да, но как **входной материал** (`inputs/markets/`), а не роль в кодовом SDD; вводится при первом реальном маркетинговом документе | ⏳ открыт |
| OQ-9 | Вводить ли условный security-проход по классификации риска? | **Требуется решение пользователя.** Рекомендация: да, отдельным предложением вместе с уровнями риска изменения; не постоянной ролью | ⏳ открыт |

Основание: при реализации `002-lifecycle-and-roles` рассматривались кандидаты в роли и были отклонены
(маркетинг/продажи/юридика — нет артефакта в SDD-конвейере; security — условный проход). Разбор —
`openspec/proposals/002-lifecycle-and-roles/design.md` §3.

Выводы для решения:
- маркетинговые и юридические материалы логично входят в цепочку **через вход** (`inputs/`), а не через роль:
  так они получают владельца (Продуктовый аналитик) без нового агента;
- условный security-проход дешевле роли: он включается по признаку (PII, аутентификация, платежи), а не работает всегда;
- оба вопроса можно закрыть одним предложением `003` вместе с уровнями риска изменения.

## Правила

1. **Нумерация `OQ-N` сквозная и не переиспользуется.** Закрытый вопрос переносится в «Закрытые», а не удаляется.
2. **У каждого вопроса есть источник** — предложение, спека или обсуждение.
3. **«Решение» = ответ пользователя**, не мнение агента. Агент готовит варианты и замеры.
4. **Закрытие = запись в [`DECISIONS.md`](DECISIONS.md)** (`D-NNN`) и, при изменении поведения, запись в `CHANGELOG.md`.
5. **Замер обязателен** для вопросов, влияющих на поведение.
6. **Открытые вопросы блокируют релиз**, если влияют на поведение (DoD релиза).
