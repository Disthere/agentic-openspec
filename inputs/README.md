# inputs/ — входные материалы от заказчика (оператора)

Сюда складываются документы, которые **задают требования** проекта: ТЗ, постановки, концепции,
макеты и примеры графики, образцы данных и форматов, референсы.

> Это **источник требований**. Ничего отсюда не удаляется: неактуальное помечается `🗄 архив` в реестре.

Правила ведения — [`openspec/standards/04-documentation.md` §4.9](../openspec/standards/04-documentation.md).

## Что куда

| Каталог | Что кладём |
| - | - |
| `briefs/` | ТЗ, постановки, требования, регламенты, приёмка |
| `concepts/` | концепции, идеи, описания продукта, презентации, заметки |
| `graphics/` | макеты, скриншоты, схемы, примеры графики/дизайна, логотипы |
| `samples/` | образцы данных, выгрузки, фикстуры, примеры форматов (csv/json/xlsx…) |

Набор каталогов — не догма: можно добавлять свои (`contracts/`, `research/`, …).

## Правила

1. **Имя файла:** `IN-NNN-<краткий-slug>.<ext>` — например `IN-001-kanban-brief.pdf`. Номер **сквозной,
   не переиспользуется**. Группу файлов одного документа оформляйте папкой `IN-NNN-<slug>/`.
2. **Регистрация обязательна:** каждый материал попадает в [`INDEX.md`](INDEX.md) —
   материал без записи в реестре для процесса не существует.
3. **Ссылки из спецификации:** Архитектор ссылается на материалы (`IN-NNN`) в разделе `## Sources`
   предложения. Требование, не опирающееся ни на `inputs/`, ни на `OQ-N`/`D-NNN`, считается выдуманным.
4. **Оригинал не правится.** Изменение требований идёт через новое предложение и/или `OQ-N`;
   сам файл остаётся неизменным.
5. **Ограничения:** никаких секретов, ключей и персональных данных. Крупные бинарники (видео, большие
   архивы) — обсудить Git LFS, иначе они раздуют репозиторий.
6. **Материал ≠ спецификация.** Материал описывает желание заказчика; спецификация —
   обязательство системы. Их связывает раздел `## Sources` и `IN-NNN`.

## Кто это использует

- **Архитектор** — обязан прочитать релевантные материалы и `INDEX.md` до написания спецификации;
  результат — раздел `## Sources` в `proposal.md`.
- **Разработчик** — читает материалы, на которые ссылается утверждённая спецификация.
- **Ревьюер** — проверяет прослеживаемость: каждое требование опирается на `inputs/`, `OQ-N` или `D-NNN`.

## Как это устроено в DSH

DSH видит эти файлы как обычные файлы воркспейса (агент читает их инструментами `fs`). Специальной
настройки не требуется — достаточно выбрать корень проекта как workspace.
