# DECISIONS — журнал решений проекта

Парный документ: открытые вопросы — в [`OPEN_QUESTIONS.md`](OPEN_QUESTIONS.md).
Изменения поведения — в [`CHANGELOG.md`](CHANGELOG.md). Архитектурно значимые решения дублируются в ADR
([`docs/architecture/adr/`](docs/architecture/adr/)).

## Журнал

### D-006 — Open Questions и Decisions как отдельные живые документы (09.11.2026, v0.3.0)

- **Статус:** ✅ действует
- **Источник:** обсуждение формата документации
- **Решение:** открытые вопросы ведутся в `OPEN_QUESTIONS.md`, принятые решения — в `DECISIONS.md`;
  источник вопросов — раздел `## Open Questions` предложений.
- **Контекст:** закрытые вопросы и решения терялись в истории переписок и в теле предложений.
- **Обоснование:** один адресуемый номер (`OQ-N`) и один номер решения (`D-NNN`) дают ссылки из кода,
  CHANGELOG и ADR; формат заимствован из практики пилотного проекта.
- **Последствия:** релиз не закрывается при открытых вопросах, влияющих на поведение (DoD 5.4).
- **Реализация:** `OPEN_QUESTIONS.md`, `DECISIONS.md`, шаблоны в `docs/`, стандарт
  [`04-documentation.md` §4.7–4.8](openspec/standards/04-documentation.md).

### D-005 — Формат Changelog: Keep a Changelog + SemVer с привязкой к задаче (09.11.2026, v0.3.0)

- **Статус:** ✅ действует
- **Источник:** OQ-6
- **Решение:** `CHANGELOG.md` в корне; заголовок `## [X.Y.Z] — YYYY-MM-DD · <суть> (<ID>)`;
  обязательная привязка к задаче; секции `Добавлено/Изменено/Исправлено/Удалено/Устарело/Безопасность`
  плюс `Не изменилось / Производительность / Миграция / Тесты`.
- **Контекст:** нужна проверяемая история изменений, связанная со спецификациями.
- **Обоснование:** `(<ID>)` = ID предложения / `spec-id` / issue; `Не изменилось` фиксирует, что дефолт прежний.
- **Последствия:** changelog пишется в том же PR; включён в DoD релиза.
- **Реализация:** `CHANGELOG.md`, [`docs/CHANGELOG-TEMPLATE.md`](docs/CHANGELOG-TEMPLATE.md),
  [`04-documentation.md` §4.6](openspec/standards/04-documentation.md).

### D-004 — Скиллы: общие глобально, проектные — в проекте (09.11.2026, v0.2.0)

- **Статус:** ✅ действует
- **Источник:** OQ-5
- **Решение:** общие скиллы — глобально (`~/.dsh/skills`, ранг 400); проектные — `<проект>/.agents/skills`
  (ранг 200). В проектах общие скиллы не дублируются.
- **Контекст:** при копировании набора в новые проекты правила начали бы расходиться.
- **Обоснование:** DSH сканирует корни по приоритету; проектный скилл перекрывает глобальный с тем же именем.
- **Последствия:** «my-project-specific» скиллы живут в проекте, всё повторно используемое — глобально.
- **Реализация:** [`dsh/README.md`](dsh/README.md) (карта корней скиллов).

### D-003 — Обвязка DeepSeek Harness: профиль `agentic-openspec` (09.11.2026, v0.2.0)

- **Статус:** ✅ действует
- **Источник:** OQ-4
- **Решение:** роли объявляются как agent presets (`@deepseek-ai/dsh-agent-preset`), персона —
  `@deepseek-ai/dsh-persona`, **модель на роль** — дочерним плагином `@deepseek-ai/dsh-agent-default-model`;
  профиль называется `agentic-openspec`.
- **Контекст:** переход на DSH; имя `desktop` в DSH зарезервировано под Electron.
- **Обоснование:** один профиль на все проекты (он глобальный), роли с разными моделями.
- **Последствия:** профиль ставится в `$DSH_HOME/profiles/`, а не в проект.
- **Реализация:** [`dsh/profile/cordis.patch.yml`](dsh/profile/cordis.patch.yml), [`dsh/install.ps1`](dsh/install.ps1).

### D-002 — Базовые инженерные стандарты C# / .NET (05.11.2026, v0.1.0)

- **Статус:** ✅ действует
- **Источник:** `openspec/standards/`
- **Решение:** C# 12+ / .NET 8+, nullable включён, warnings-as-errors, анализаторы
  (NetAnalyzers + Sonar + Meziantou); `.editorconfig` на базе dotnet/runtime; покрытие >80% (Domain >90%).
- **Обоснование:** единый стиль и автоматическая проверка вместо устных договорённостей.
- **Реализация:** [`Directory.Build.props`](Directory.Build.props), [`Directory.Packages.props`](Directory.Packages.props),
  [`.editorconfig`](.editorconfig), стандарты `01`–`11`.

### D-001 — Каталог предложений `openspec/proposals/` (05.11.2026, v0.1.0)

- **Статус:** ✅ действует
- **Источник:** обсуждение структуры SDD
- **Решение:** предложения живут в `openspec/proposals/<NNN-slug>/` (вместо `changes/` у OpenSpec).
- **Обоснование:** привычный нейминг + сохранена OpenSpec-совместимость формата требований.
- **Реализация:** [`openspec/proposals/`](openspec/proposals/), шаблон `000-template.md`.
