## 1. Контекст: перенос в `sdd/`

Между прошлым аудитом и этой сессией весь SDD-контент переехал в одну папку `sdd/`
(коммит `259b86a`). Перенос **аккуратно обновил то, что исполняется**, и **не обновил то, что
читают люди и модели**. Из-за этого набор оставался полностью зелёным (все 8 прогонов гейтов
exit 0) при 11 сломанных путях.

**Корневая причина, почему это не ловилось:** ни один гейт не читает `.clinerules`, не резолвит
ссылки в нём и не сверяет прозу документов с фактами репозитория.

### 2.5 Новое правило взаимодействия (N-I)

**Находка.** В конце этой сессии два решения владельца (P0-4 и P1-8) были предложены **таблицей
в тексте отчёта** вместо диалога. Формально §7.1 («спрашивай вариантами») соблюдён — варианты есть,
первый помечен рекомендуемым. Фактически диалога не произошло: владельцу пришлось отвечать вручную
и указать на дефект. Правило соблюдалось буквально и нарушалось по сути.

**Причина.** §7.1 описывал *формат* вариантов (2–4, первый — рекомендуемый, следствие у каждого), но не
описывал *носитель*: «варианты в прозе» и «диалог с выбором» считались одним и тем же.

**Правка.** Формулировка усилена в пяти местах:

| Файл | Что добавлено |
| - | - |
| [`AGENTS.md`](../../../AGENTS.md) §7.1 | раздел «Отчёт с вариантами — ещё не диалог»: требование инструмента выбора, таблица «ситуация → правильно/неправильно», почему это отдельное правило |
| [`constitution.md`](../../../openspec/constitution.md) §1 п. 6 | «варианты, перечисленные текстом в отчёте, диалогом не являются: человек выбирает вариант в интерфейсе» |
| [`.clinerules`](../../../../.clinerules) | та же норма в кратком зеркале |
| [`SET-AUDIT.md`](../../SET-AUDIT.md) | «Второе ключевое правило» — потому что нарушение произошло именно в сессии аудита |
| [`AUDIT-PROMPT.md`](../../AUDIT-PROMPT.md) | в готовый промпт добавлено требование задавать решения отдельными диалогами |

**Проверка.** `check-canon-parity` exit 0 (канон 331 строка / зеркало 61): норма живёт в каноне,
зеркало маршрутизирует, противоречий запретам нет.

## 4. Ограничения этой сессии

- **Не проверял живьём:** нагрузочный контур, десктопный стек (Avalonia/LLamaSharp), поведение
  пресета в Web UI после правки персоны (проверено только через `--dump-config`).
- **`dotnet test` / `dotnet format`** недоступны в среде: `test` падает на named pipes песочницы,
  `format` требует восстановления пакетов. Вердикт опирается на прямой запуск `Smoke.Tests.exe`
  и `dotnet build`.
- **CI на GitHub** не наблюдался (`gh run list` без сети): вывод сделан разбором workflow и
  локальным прогоном его шагов.
- **P0-4** (цикл не замкнут: `specs/` пуст, 8 дельт в `docs/legacy/set-history/specs/`) —
  **осознанно оставлен**, решение владельца: вариант A («оставить как есть», см. §5).
- **P1-8** (FluentAssertions без машинной проверки) — долг зафиксирован честно в тексте стандарта
  вместо ложного заявления о CI-шаге; решение владельца — вариант A, см. §5.
- **P2-18** (CRLF в рабочем дереве при `eol=lf` в `.gitattributes`) — причина `core.autocrlf=true`
  на этой машине, т.е. локальная настройка, а не дефект набора. Индекс чист (`i/crlf` = 0).
- **Ложные срабатывания при проверке:** `OQ-8` в `.agents/skills/code-review/references/findings.md`
  и `OQ-13` в `ADOPTION.md` — исторические упоминания образца формата, не живые ссылки на реестр;
  `OQ-13` помечен как замороженный, `OQ-8` оставлен как пример в шаблоне находок.

## 5. Решения владельца по открытым пунктам

Оба вопроса заданы **диалогом с вариантами** ([`AGENTS.md`](../../../AGENTS.md) §7.1), по одному
решению на диалог. Выбраны рекомендованные варианты — правок не потребовалось, зафиксировано здесь,
а не в `DECISIONS.md` (конституция §1 п. 7: история набора в реестры шаблона не пишется).

| # | Вопрос | Решение | Следствие |
| - | - | - | - |
| 1 | Что делать с legacy-исключением для `specs/` (P0-4) | **A — оставить как есть** | Чистый шаблон проходит собственный гейт; `specs/` наполнится при первом архивном предложении продукта. Семантика «delta из `docs/legacy/set-history/specs/` считается влитой» сохраняется намеренно |
| 2 | Что делать с проверкой версии FluentAssertions (P1-8) | **A — оставить долгом в тексте** | `01-code-style.md` честно говорит: проверяется при ревью, машинного шага нет. Новый шаг CI не добавлялся |

**Почему вариант A для P0-4, а не флаг в `config.yaml`.** Исключение — не настройка, а следствие
природы артефакта: `specs/` — живые спецификации **продукта**, а дельты набора — история **набора**.
Разнести их флагом значило бы разрешить произвольную подмену, тогда как текущее поведение
описывает ровно один случай и задокументировано комментарием в самом гейте.

**Почему вариант A для P1-8, а не шаг CI.** Урок аудита 2026-11-12 (§4.5): два новых шага CI,
написанные «на глаз», уронили сборку по причинам, не относящимся к качеству набора. Машинная
проверка версии пакета — задача отдельного предложения с локальным прогоном, а не побочная правка
формулировки. Долг зафиксирован там, где его увидит ревьюер.

**Условие пересмотра.** Оба решения пересматриваются, если: (P0-4) появится продуктовое предложение,
чей архив должен вливать дельту именно в `specs/`, — исключение проверится на реальном случае;
(P1-8) FluentAssertions 8.x появится в `Directory.Packages.props` — тогда нужен машинный стоп,
а не текстовое правило.
