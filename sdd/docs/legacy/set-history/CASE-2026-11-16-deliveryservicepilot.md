## 3. Найденные дефекты

### K-1 (P0) — Review gate не оставил артефакта; документы противоречат друг другу

| Источник | Утверждение |
| - | - |
| `STATUS.md:14` | «…→ Review **`Pass`** → Release → Archive» |
| `CHANGELOG.md:47` | «принято: **вердикт `Pass`** (десятый проход, две оси)» |
| `ADR-001:11` | «принято независимым ревью (**`Pass`**, десятый проход)» |
| `acceptance.md:452` | «Вердикт ревью: `Pass` / `Fail` — **не выносился**» |

Конституция §3 п. 4 и §7 требуют для фазы Review артефакт — «вердикт ревью». В каталоге
предложения файлов пять: `proposal.md`, `tasks.md`, `acceptance.md`, `performance.md`,
`contracts/`. **Вердикта нет.**

Машинное подтверждение: `collect-metrics.ps1 -Json` → `"verdict": null`.

Ревью при этом **проводилось**: в `tasks.md` разделы «Исправление блокирующих находок ревью
16.11.2026» и «корневой причины `P-09`», находки `S-04`, `P-09`, `P-14`, `S-16` закрыты.
Дефект не в работе, а в том, что **доказательство фазы не было создано файлом** — и ни один гейт
этого не потребовал.

**Почему не поймали:** `validate-proposals.ps1 -Archived` проверял чекбоксы, `Status: Done`,
дельту в `specs/` и заполненность `acceptance.md` — но не наличие вердикта.

### K-2 (P1) — `SKIP` зачитывался как пройденная проверка

`check-dsh-profile.ps1` при отсутствии `dsh.cmd` печатал `SKIP` и возвращал exit 0. В кейсе
`STATUS.md:56` ссылался на гейты как на пройденные — форма «зелено, потому что не проверяли».

### K-3 (P1) — `METRICS.md` устарел на 4 дня и противоречил фактам

```
> Собрано автоматически 2026-11-12 18:26
## 4. Архив завершённых
_Архив пуст._        ← а в архиве уже было завершённое предложение
```

Причина: файл в `.gitignore`, скрипт последний раз запускали до архивации; правило «метрики не
ведутся руками» соблюдено, но перегенерация перед закрытием (канон §7 шаг 10) не выполнена.

### K-4 (P1) — `check-doc-numbers.ps1` пропускал проверку и это выглядело как успех

```
SKIP  активных предложений: 0 — сверка чисел не применима
EXIT=0
```

Гейт смотрит только на активные предложения (`$_.Name -ne 'archive'`); после архивации он
проверяет пустоту. `STATUS.md:56` при этом заявлял «Числа в документах = фактам ✅
`tools/check-doc-numbers.ps1`» — то есть зелёный статус относился к проверке, которая ничего
не проверила.

### K-5 (P2) — Шесть закрытых вопросов помечены как открытые

В `proposal.md` §Open Questions проза: «Все шесть вопросов приняты с рекомендованными дефолтами…
зафиксированы `D-035`…`D-040`», но все шесть пунктов — `- [ ]`. Любой парсер чекбоксов видит шесть
незакрытых вопросов.

### K-6 (P2) — Косметика шаблона: 8 вхождений `)))`

`proposal.md`: `…config.yaml`](../../../config.yaml)))`. Ссылки резолвятся, на гейт не влияет.
След шаблона-предшественника; в текущем `000-template.md` набора такого нет — уже исправлено.

## 5. Главный вывод

**Инженерно кейс сильный; процессно провален там, где гейт существовал только как текст.**
262 зелёных теста, честные замеры, независимые улики, оформленные исключения — и при этом
гейт Review, объявленный обязательным в конституции §3 п. 4, не оставил после себя ничего, кроме
упоминаний в `CHANGELOG.md` и `ADR-001`.

Это диагноз **набору**: проверка «фаза Review пройдена» была словесной. Теперь она машинная, и
ровно этот кейс стал бы красным: архив без `review.md` → `V-архив` FAIL.

Урок в копилку, совпадающий с прошлым аудитом: **всякий гейт, который нельзя провалить командой,
будет обойдён — не по злому умыслу, а потому что «работа сделана» и без файла.** Форма
соблюдалась (`VERDICT` в тексте есть), артефакт отсутствовал.
