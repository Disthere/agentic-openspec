# Review — <NNN-slug>

> **Это артефакт фазы Review** (конституция §7: «вердикт ревью»). Без него предложение нельзя
> перевести в `Status: Done` и убрать в `archive/` — это машинно проверяется
> (`validate-proposals.ps1 -Archived`: ищет первую строку `VERDICT: Pass|Fail`).
>
> **Первая строка файла — только вердикт.** `VERDICT: Pass` или `VERDICT: Fail`, без «меню»
> (`Pass / Fail`) и без пояснений в той же строке: гейт читает префикс, а человек — смысл ниже.

## Оси

Ревью двухосевое ([`code-review`](../../../../.agents/skills/code-review/SKILL.md));
оси выполняются независимо и **не** объединяются в один отчёт.

| Ось | Что проверяет | Вердикт |
| - | - | - |
| **Standards** | Соответствие задокументированным стандартам проекта (`.editorconfig`, `openspec/standards/*`, схемы, базлайн запахов) | `Pass` / `Fail` |
| **Spec** | Покрытие требований спецификации, регрессии поведения, существующие вызывающие, корневая причина багфикса | `Pass` / `Fail` |

**Итог:** `Pass` — только если обе оси `Pass`.

## Находки

Формат и жизненный цикл — [`findings.md`](../../../../.agents/skills/code-review/references/findings.md):
устойчивый `ID` (`S-n` для Standards, `P-n` для Spec), ось, `Where` (`file:line`), `Breaks`,
улика, класс `hard`/`judgement` и ровно одна диспозиция (`fixed` / `rejected` / `deferred`).

| ID | Ось | Where | Breaks | Улика | Класс | Диспозиция |
| - | - | - | - | - | - | - |
| `S-01` | Standards | `<файл:строка>` | `<какой стандарт/пункт>` | `<команда или наблюдение>` | `hard` | `fixed` |
| `P-01` | Spec | `<файл:строка>` | `<какое требование R*/сценарий>` | `<команда или наблюдение>` | `hard` | `fixed` |

**Блокирующие** (дают `Fail`): нарушение задокументированного стандарта, разрыв трассируемости,
непокрытый сценарий спецификации. **Не блокирующие** — запахи кода: они в таблицу попадают,
но `Fail` не дают.

## Что проверено независимо

- [ ] `git status --porcelain` до и после ревью — дерево не менялось ревьюером
- [ ] Не тот же агент, что писал код (конституция §3 п. 4)
- [ ] Гейт прогнан самостоятельно, вывод зафиксирован (не взят из отчёта разработчика)
- [ ] Числа в документах сверены с фактом (тесты/требования/сценарии), а не переписаны
- [ ] Улики QA перепроверены, а не приняты на слово
