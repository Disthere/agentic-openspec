# HANDOFF-пакет наружу — универсальный шаблон

> Скопируйте в `handoff/<NNN-slug>-vX.Y/` (или в отдельный приватный репозиторий) и заполните `MANIFEST.md`.
> Правила — [`openspec/standards/03-handoffs.md` §3.5](../openspec/standards/03-handoffs.md).

## Структура пакета

```text
handoff/001-kanban-v1.0/
├── MANIFEST.md          # ← шаблон ниже (обязателен)
├── spec.md              # требования и сценарии в терминах исполнителя
├── contracts/           # openapi.yaml / *.proto / event schemas
├── deliverables.md      # что и в каком виде сдаётся
├── acceptance.md        # как принимаем (тесты, команды, границы)
├── env.md               # окружение, сборка, песочница
└── standards/           # ТОЛЬКО применимый срез наших стандартов
```

## Явно НЕ входит

- материалы заказчика: `inputs/` (конфиденциально);
- внутренние решения и вопросы: `DECISIONS.md`, `OPEN_QUESTIONS.md`;
- процессы и обвязка агентов: `.clinerules`, `.agents/`, `dsh/`;
- история предложений, чужие сервисы, инфраструктура, секреты и строки подключения.

## Что требуется от исполнителя

- <артефакты и их формат>;
- сборка и прогон тестов против `contracts/` до сдачи.

## Как принимаем

- команды: `dotnet restore && dotnet build -c Release && dotnet test -c Release`;
- contract-тесты против `contracts/`;
- чек-лист DoD (срез из `standards/05-definition-of-done.md`);
- при необходимости — нагрузочный прогон с воспроизводимым сценарием.

## Чек-лист вычистки перед отправкой

- [ ] нет секретов, ключей, токенов, строк подключения;
- [ ] нет персональных данных и материалов заказчика из `inputs/`;
- [ ] нет внутренних решений/вопросов/ADR «почему решили не так»;
- [ ] нет ссылок на внутренние сервисы, репозитории и инфраструктуру;
- [ ] контракты содержат версию и семантику ошибок;
- [ ] критерии приёмки объективны (тесты/команды), а не «на усмотрение»;
- [ ] `MANIFEST.md` заполнен: состав и исключения перечислены;
- [ ] пакет проверен независимо (Ревьюер), вердикт зафиксирован.
