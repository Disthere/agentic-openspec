# SLO (цели уровня сервиса)

Определяют, что значит «сервис работает». SLO не заявляется без нагрузочного теста в описанном окружении
(см. [`../../openspec/standards/11-performance.md`](../../openspec/standards/11-performance.md)).

## SLI и целевые значения

Заполняется на сервис/сценарий.

| Сервис / сценарий | SLI | Цель | Окно |
| - | - | - | - |
| <service> / <endpoint или операция> | Доступность | 99.9% | 30 дней |
| <service> | Latency p95 | < 200 ms | 30 дней |
| <service> | Latency p99 | < 500 ms | 30 дней |
| <service> | Доля ошибок (5xx) | < 0.1% | 30 дней |

## Error budget

- Бюджет ошибок = `1 − цель`. Исчерпание бюджета останавливает рискованные изменения и запускает работу над надёжностью.
- Burn-rate алерты: быстрый (2% бюджета за 1 час) и медленный (10% за 3 дня).

## Что подтверждает SLO

- Метрики: latency (p50/p95/p99), коды ошибок, throughput, saturation — см. [`../../openspec/standards/10-observability.md`](../../openspec/standards/10-observability.md).
- Трассы и структурные логи с корреляцией.
- Health-checks `/health/live`, `/health/ready`.

## Регулярность

- Ревизия SLO — при изменении сценариев/нагрузки или инцидентах.
- Изменение SLO — через согласованное предложение, не «на ходу».
