# Сессия аудита SDD-набора — протокол запуска

**Назначение:** этот файл — для случая, когда цель сессии **не продукт**, а сам набор:
найти недостатки в SDD-концепции, проверить закрытие старых находок, найти новые.

> Обычная сессия (разработка продукта) начинается иначе — см. [`ADOPTION.md`](./ADOPTION.md) §2.
> Здесь — другой режим: **аудит, а не реализация**.

---

## Когда это нужно

- Замечаете, что правило в каноне не работает на практике.
- Хотите проверить, не разошлись ли документы после серии правок.
- Нужна ретроспектива: что из прошлого аудита действительно закрыто.
- Готовите набор к передаче и хотите найти дыры до получателя.

---

## Промпт для новой сессии

Скопируйте целиком в главную сессию с пресетом `sdd`:

```text
Ты — Оркестратор SDD. Задача этой сессии — АУДИТ САМОГО НАБОРА, не продукта.

Прочитай в таком порядке:
1. AGENTS.md — канон правил (обрати внимание на §7.1: вопросы задаются вариантами)
2. openspec/constitution.md — высший приоритет, особенно §1 и §7
3. STATUS.md — где мы сейчас
4. docs/legacy/set-history/ASSESSMENT.md — прошлый аудит (11 P0, 21 P1, 33 P2)
5. docs/legacy/set-history/PLAN.md — план исправлений; все 5 батчей выполнены

Задача:
— проверь, что из прошлых находок действительно закрыто (не «по словам», а командой);
— найди новые недостатки: противоречия между документами, неработающие правила,
  декоративные гейты, дубли, устаревшие ссылки;
— проверь, что правила, добавленные ПОСЛЕ прошлого аудита, соблюдаются
  (Spec First для продукта, §7.1 про варианты, STATUS.md, метрики).

Правила работы в этой сессии:
— сначала факты командами (tools/*.ps1, --dump-config, git log), потом выводы;
— каждую находку подтверди воспроизведением, укажи файл:строку;
— ничего не меняй без моей команды;
— вопросы ко мне — вариантами ответов (AGENTS.md §7.1).

Формат результата:
1) таблица «находка → приоритет → улика → куда чинить»;
2) отдельно: что из прошлого аудита НЕ закрыто и почему;
3) отдельно: новые находки с приоритетом.

Не начинай правки. Сначала отчёт.
```

## Ключевое правило этой сессии

**Правки набора не требуют полного SDD-цикла.** Это зафиксировано в
[`openspec/constitution.md`](../openspec/constitution.md) §1 п. 7:

| Что меняется в наборе | Как оформляется |
| - | - |
| Канон, стандарты, документация процесса | запись в `docs/legacy/set-history/` + сообщение коммита |
| Пресет DSH, роли, конфигурация | то же + `docs/ci/check-dsh-profile.ps1` зелёный |
| Инструменты `tools/*.ps1` | то же + прогон инструмента и **негативный тест** |
| Схемы, шаблоны предложений | то же + `tools/validate-proposals.ps1 -All -Archived` |

Обязательны всегда: **проверка командой, негативный тест гейта, осмысленный коммит**.
Фиктивная спецификация вместо этого — нарушение, а не «строгость».

> **Почему записи идут в `docs/legacy/set-history/`, а не в `DECISIONS.md`.** Реестры — часть шаблона,
> при раздаче они сброшены к пустым формам. История набора в них уедет в чужой проект.

## Известные слабые места (намеренно не исправлены)

Список честный: это места, где набор **знает** о своей ограниченности.
Не считайте их находками — они зафиксированы.

| Слабое место | Почему оставлено |
|---|---|
| Изоляция QA и Ревьюера — дисциплинарная, не техническая | В DSH 0.2.2-rc.1 нет read-only permission-preset (D-021, задача 3.8) |
| Правило §7.1 (вопросы вариантами) не проверяется машиной | Это форма общения, а не файл; `check-canon-parity` следит лишь за наличием правила |
| `preset-sdd` собирается вручную из `standard` | Три ошибки в батче 3 показали риск; генератор — кандидат в отдельное предложение |
| Стейте-кэш DSH: приложение читает бандл при старте | Ловится предупреждением в `check-dsh-profile.ps1`, лечится перезапуском |
| `docs/session/` не коммитится | Осознанно: состояние сессии не часть шаблона |

## Чего делать НЕ надо

- Не начинать с правок. Сначала отчёт с уликами.
- Не доверять `STATUS.md` на слово — сверять с `openspec/proposals/`.
- Не считать «зелёный гейт» доказательством: у каждого скрипта есть негативный тест, проверьте, что он падает.
- Не переписывать стандарты 01–12 по содержанию — они вне объёма аудита набора.
