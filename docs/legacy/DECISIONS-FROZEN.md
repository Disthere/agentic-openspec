# DECISIONS — журнал решений agentic-openspec

Формат: номер · дата · решение · статус · обоснование/источник.
Статусы: **ACCEPTED** — принято; **PROPOSED** — предложено, ждёт подтверждения пользователя
(см. [`OPEN_QUESTIONS.md`](OPEN_QUESTIONS.md)); **SUPERSEDED (D-XXX)** — заменено; **REJECTED** — отклонено.

Парный документ: открытые вопросы — в [`OPEN_QUESTIONS.md`](OPEN_QUESTIONS.md).
Изменения поведения — в [`CHANGELOG.md`](CHANGELOG.md).

**Статус `ACCEPTED` с открытым парным `OQ-N`.** Допустимая форма для случая «поведение принято
утверждённым предложением, а уточнение детали осталось за владельцем»: решение действует, а уточнение
перечислено в колонке «Статус» (`… ; <что осталось> — OQ-N`). Закрытие `ACCEPTED` на открытый вопрос
целиком (`OQ-N` → `✅ закрыт`) означает, что уточнений не осталось.

## D-003 — роли и модели в DeepSeek Harness (подробности)

DSH собирает профиль как композицию плагинов Cordis; роли объявляются декларативно.

| # | Механизм | Что даёт |
| - | - | - |
| a | `@deepseek-ai/dsh-agent-preset` (`config.id`, `plugins[]`) | именованная роль (Architect / csharp-dev / reviewer) со своей композицией |
| b | `@deepseek-ai/dsh-agent-default-model` внутри `plugins:` | **своя модель на роль** (архитектору — сильнее, ревьюеру — независимую) |
| c | `@deepseek-ai/dsh-persona` (`prefix`) | персона роли; текст короткий и ссылается на `.agents/*.md` (без дублирования правил) |
| d | `agent-preset-registry` (`default: csharp-dev`) | роль по умолчанию для новых сессий |

Следствия:
- профиль **глобальный** (`$DSH_HOME/profiles/agentic-openspec`), один на все проекты;
- имя `desktop` недоступно (зарезервировано под Electron) — отсюда `agentic-openspec`;
- корректность композиции проверяется через `--dump-config`.

- появился адресуемый след: `OQ-N` → `D-NNN` → версия в `CHANGELOG.md`.

## D-007 — провайдер и модели DSH-профиля (подробности)

Привязка живёт в [`dsh/profile/cordis.patch.yml`](dsh/profile/cordis.patch.yml) двумя записями-переопределениями
(оба id объявлены бандлом `dsh-base`, поэтому это не `insert`):

| # | Механизм | Что даёт |
| - | - | - |
| a | `- id: llm-pi-ai` + `config.providers.routerai` | маршрут провайдера: `baseURL: https://routerai.ru/api/v1`, `api: openai-completions`, ключ из `ROUTERAI_API_KEY`, список моделей в `models` |
| b | `- id: agent-default-model` | дефолт модели для агентов от точек входа: `routerai` / `deepseek/deepseek-v4.1-flash` |
| c | (опционально) `@deepseek-ai/dsh-agent-default-model` в `plugins:` пресета | своя модель на конкретную роль — когда понадобится развести |

Следствия:
- все шесть ролей работают на одной модели; разведение по ролям — одна строка в нужном пресете;
- ключ API **не хранится в репозитории** — только имя переменной окружения;
- список моделей в селекторе приложения формируется из блока `models`; расширяется там же.

## D-008 — приведение существующей документации к структуре набора (подробности)

Два шага, разделённые гейтом человека: инвентаризация (**только чтение**, до baseline-спецификации) и
применение (после первого изменения) — по утверждённым построчно строкам реестра.

| # | Механизм | Что даёт |
| - | - | - |
| a | `docs/legacy/INDEX.md` — реестр `LEG-NNN` («где живёт · владелец · потребитель · актуальность · наш артефакт · действие · статус») | известен состав документации; B2 не восстанавливает по коду то, что уже описано в ТЗ/ADR |
| b | Карта соответствий «их документ → наш артефакт» (ADR → `docs/architecture/adr/`, ТЗ → `inputs/` + `IN-NNN` + спека, runbook/SLO → `docs/operations/`) | у каждого документа есть адрес в нашей структуре либо явное «нет соответствия» |
| c | Гейт: применяются только строки, утверждённые человеком («утверждаю LEG-NNN») | необратимые действия не происходят без решения владельца; можно утвердить 5 строк из 40 |
| d | Документ-указатель вместо копии (статус-маркер + ссылка + `LEG-NNN`, без правил поведения) | «источник истины один»: два описания одного поведения не остаются |
| e | Маркеры `🗄 архив` / `🌐 внешний` + строка реестра, ничего не удаляется | история проекта сохраняется, старые закладки и ссылки не дают 404 |
| f | Чужой `CHANGELOG.md` **разбирается**: актуальные записи → проектный `CHANGELOG.md` с указанием источника `LEG-NNN`; исторические → дословно в `docs/legacy/CHANGELOG-FROZEN.md` за строкой-указателем | действующий changelog один (§4.6), ничего не теряется, читатель не лишается актуальных сведений |
| g | Расхождение «документ vs код» → `OQ-N` с рекомендуемым дефолтом | молчаливых решений нет (`constitution.md` §1 п. 5); код — факт, документ — намерение |
| h | Проверка «ответ за один переход»: список вопросов + промпт + таблица Pass/Fail с числом переходов | результат воспроизводим и сравним до/после применения |

Следствия:
- правило и формат — `openspec/standards/04-documentation.md` §4.10; готовые промпты — `docs/ADOPTION.md`
  §3 (B1a) и §7 (B6); шаблоны в целевом проекте — `docs/legacy/`;
- новая роль не вводится (D-014): карту и переносы делает `architect`, проверку — `reviewer`,
  применение фиксирует Оркестратор;
- `OQ-15`…`OQ-20` — закрыты ответами владельца 10.11.2026: реестр — каталог `docs/legacy/` (D-009),
  внешняя документация — только указатели (D-011), оригинал всегда оставляется указателем (D-010),
  чужой changelog разбирается, а не замораживается (D-012), код — факт (D-013), проверка — чек-лист
  и промпт, скрипт позже (D-014).
