# docs/legacy/ — документация проекта, существовавшая до внедрения SDD

Здесь ведётся **документация проекта, существовавшая до внедрения SDD**: свои ADR, ТЗ и постановки,
`docs/` с другой иерархией, wiki/Confluence/Google Docs вне репозитория, исторические и архивные
документы, свой `CHANGELOG.md`. Это не второй источник требований, а **реестр того, что уже есть**,
и карта соответствий «их документ → наш артефакт».

> **Главное правило.** Реестр хранит **метаданные**: где документ живёт, чей он, кто им пользуется,
> актуален ли он, куда переносится. Реестр **не хранит и не пересказывает правила поведения** —
> нормативный текст живёт только в нашем артефакте (`openspec/`, `docs/architecture/`, `docs/operations/`,
> `inputs/`).

Состав каталога:

| Файл | Что внутри |
| - | - |
| [`README.md`](README.md) | правила ведения: статусы, шаблон строки реестра, шаблон документа-указателя, маркер «оставить на месте» |
| [`INDEX.md`](INDEX.md) | реестр документов `LEG-NNN` и карта соответствий «их документ → наш артефакт» |
| [`CHANGELOG-FROZEN.md`](CHANGELOG-FROZEN.md) | историческая часть чужого changelog после разбора: актуальное перенесено в проектный `CHANGELOG.md` |

Нормы — [`openspec/standards/04-documentation.md` §4.10](../../openspec/standards/04-documentation.md);
высший приоритет — [`openspec/constitution.md`](../../openspec/constitution.md); устройство соседнего
реестра-образца — [`inputs/README.md`](../../inputs/README.md) и [`inputs/INDEX.md`](../../inputs/INDEX.md).

## Словарь статусов

Ядро словаря общее с входными материалами ([`inputs/INDEX.md`](../../inputs/INDEX.md)), чтобы человек
не учил второй язык пометок; четыре последних значения описывают судьбу документа, которой у входного
материала нет.

| Статус | Что значит |
| - | - |
| `⏳ не разобран` | документ внесён в реестр, решение по нему не принято |
| `🔎 в разборе` | документ сверяется с кодом и нашими артефактами, карта соответствий уточняется |
| `✅ учтён (<NNN-slug>, D-NNN)` | содержание документа учтено нашим артефактом; указаны предложение и решение |
| `🗄 архив (не актуален)` | документ оставлен на месте как история проекта, источником истины не является |
| `➡ указатель` | содержание перенесено в наш артефакт, на старом месте — документ-указатель без нормативного текста |
| `🌐 внешний` | документ живёт вне репозитория; в реестре — URL, владелец и причина |
| `❓ вопрос (OQ-N)` | судьба документа ждёт ответа владельца, вопрос зарегистрирован в `OPEN_QUESTIONS.md` |
| `❌ отклонён (D-NNN)` | решено не переносить и не учитывать документ; основание — запись `D-NNN` |

## Шаблон строки реестра

Колонки [`INDEX.md`](INDEX.md) — ровно в этом порядке:

```markdown
| ID | Документ | Где живёт | Владелец | Потребитель | Актуальность | Наш артефакт | Действие | Статус | Примечание |
| - | - | - | - | - | - | - | - | - | - |
| LEG-NNN | <название или путь> | <путь в репозитории или URL> | <команда/человек> | <кто пользуется> | <актуальность> | <путь нашего артефакта или «нет соответствия»> | <действие> | `⏳ не разобран` | <причина, ограничения, номер OQ/D> |
```

## Документ-указатель

Перенесённый документ **не удаляется**: на его месте остаётся указатель. Обязательные свойства
указателя — все три, иначе он не указатель:

1. **статус-маркер** в первых строках (видно, что документ больше не источник истины);
2. **рабочая ссылка** на наш артефакт (относительный путь, который резолвится);
3. **нет нормативного текста** — ни правил, ни требований, ни схем поведения.

```markdown
# <Название документа> — перенесено

> **Статус:** ➡ указатель · **Перенесено в:** [`<наш артефакт>`](<относительная ссылка>) ·
> **Предложение:** `openspec/proposals/<NNN-slug>/` · **Дата:** <YYYY-MM-DD>

Правил поведения этот файл не содержит: единственный источник — артефакт по ссылке выше.
Историю документа см. в реестре `docs/legacy/INDEX.md` (запись LEG-NNN).
```

## Маркер «оставить на месте»

Документ, который остаётся на месте (архив, материал без соответствия), получает в первых строках
маркер-блок. Содержимое при этом не переписывается: правка нужна только ради маркера.

```markdown
> 🗄 **Архив (не актуален).** Оставлен как история проекта; не является источником истины.
> Актуальное описание: [`<наш артефакт>`](<ссылка>). Реестр: `docs/legacy/INDEX.md` (запись LEG-NNN).
```

Для внешней документации маркер ставится **в реестре** (`🌐 внешний` + URL, владелец и причина
в `Примечании`): править чужую страницу процедура не имеет права. Строка реестра — единственное место,
где такая отметка существует.

## Проверка «ответ за один переход»

Результат приведения документации проверяется воспроизводимо, а не «на глаз»: фиксированный список
вопросов нового участника и таблица Pass/Fail с числом переходов от точек входа (`README.md`,
`AGENTS.md`, `docs/legacy/INDEX.md`). Переход — это ссылка, по которой нужно пройти, чтобы получить
ответ. Машинно проверяется:

- [ ] все ссылки в `docs/legacy/INDEX.md` резолвятся;
- [ ] у каждой строки реестра есть наш артефакт либо явное действие;
- [ ] архивные документы помечены, внешние отмечены `🌐` в реестре;
- [ ] документы-указатели соответствуют шаблону и не содержат правил поведения.

## Правила

1. **Ничего не удаляется.** Неактуальное помечается (`🗄 архив`), перенесённое становится указателем;
   удаление — отдельное решение владельца, а не шаг процедуры
   ([`04-documentation.md` §4.9](../../openspec/standards/04-documentation.md)).
2. **Один источник истины на каждое поведение.** Содержание либо переносится в наш артефакт, либо документ
   становится указателем без нормативного текста; два параллельных описания недопустимы
   ([конституция §1 п. 3](../../openspec/constitution.md)).
3. **Расхождение «документ vs код» не решается молча.** Код — фактическое поведение (baseline), документ
   помечается устаревшим или замещаемым, расхождение выносится в `OPEN_QUESTIONS.md` как `OQ-N`
   с рекомендуемым значением по умолчанию
   ([конституция §1 п. 5](../../openspec/constitution.md),
   [`04-documentation.md` §4.7](../../openspec/standards/04-documentation.md)).
4. **Чужой `CHANGELOG.md` разбирается, а не копируется вслепую.** Актуальные записи переносятся
   в проектный `CHANGELOG.md` как датированная история с указанием источника `LEG-NNN`; исторические —
   дословно в [`CHANGELOG-FROZEN.md`](CHANGELOG-FROZEN.md) за одной строкой-указателем. Ничего не теряется
   ([`04-documentation.md` §4.10](../../openspec/standards/04-documentation.md)).
