## 3. Новые находки

### P0 — блокирующие

**N-1. Гейт «канон = зеркало» односторонний.** Правило, живущее только в зеркале, не ловится.
Негативный тест: строка «использовать `msbuild` вместо dotnet CLI», добавленная в `.clinerules` →
exit 0, «правила не живут только в зеркале». Причина: `check-canon-parity.ps1:70-89` проверяет
только направление «канон → зеркало»; обратной проверки нет. Утверждение `:127` ложно.
Побочно: `Href` ищется по всему файлу, а не рядом с якорем, поэтому 2 из 12 якорей (`nullable`,
`warnings-as-errors`) зачтены лишь потому, что «AGENTS.md» встречается в зеркале где-то ещё.
*Исправлено, см. §4.*

**N-2. Валидатор ссылок не видит ссылки после inline-кода.** `validate-proposals.ps1:450-451`
вырезает код паттерном ``'`[^`\n]*'`` без требования закрывающего бэктика: закрывающий бэктик
стартует новый матч и стирает остаток строки. Демонстрация:

Строка со ссылкой ДО первого inline-кода — проверяется:

```text
before:  [plain] ( ./no-such-1.md )   и потом `code` …
              ^^^^^^^^^^^^^^^^^^^^^^ видно гейту → FAIL
```

Строка, где перед ссылкой есть inline-код, — не проверяется, остаток строки стёрт:

```text
before:  `code` и ещё [ `x` ] ( ./no-such-2.md ) конец
         ^^^^^^ матч «`code» съедает всё до конца строки
after :  ''''                          ← ссылки больше нет в тексте
```

Проверяются только ссылки **до** первого inline-кода в строке. Тот же баг продублирован в
`Test-RelativeLinks` (`:324-325`). В живых `.md` — 455 ссылок с бэктиками в тексте, все невидимы.
Итог: при 15 реально битых ссылках гейт рапортует успех. Реально сломаны:

| Ссылка | Цель | Факт |
| - | - | - |

| `.agents/README.md:36` | `../dsh/profile/cordis.patch.yml` | в `dsh/profile/` только `cordis.yml` (D-017) |
| `openspec/standards/04-documentation.md:164` | `../../docs/INPUTS-TEMPLATE.md` | файл удалён (P2-5) |
| `docs/SESSION-START-TEMPLATE.md:9` | `AGENTS.md`, `openspec/constitution.md` | шаблон лежит в `docs/`, нужны `../` |
| `docs/CLEANUP.md:12-22` | `./LICENSE`, `./CHANGELOG.md`, … (10 шт.) | файл в `docs/`, цели в корне |

*Исправлено, см. §4.*

## 6. Ограничения этого аудита

- Не проверял живьём: нагрузочный контур (`performance.md`), десктопный стек (Avalonia/LLamaSharp),
  реальное поведение ролей в Web UI после правок пресета.
- Сборка/формат/тесты через `dotnet` ограничены средой (нет сети, песочница named pipes) — вердикт по
  ним опирается на прямой запуск `Smoke.Tests.exe` и на зелёный CI, а не на локальный `dotnet test`.
- Не юридическая консультация: по P1-12 фиксирую факты (противоречие внутри `THIRD-PARTY.md`), а не
  квалификацию.
- §7.1 (вопросы вариантами) машиной не проверяется — это форма общения; проверял только наличие
  правила и его соблюдение в этой сессии.
