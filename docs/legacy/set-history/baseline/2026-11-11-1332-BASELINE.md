## Блокер записи — РЕШЁН

Причина: дочерний процесс песочницы работает на **низком уровне целостности**, а у подкаталогов
воркспейса отсутствовала обязательная метка Low (у корня она была). Windows не даёт процессу Low
писать в объект без метки / с меткой Medium. DACL при этом был в порядке — поэтому штатный
ACL-ремонт не помог.

Устранено проставлением той же метки, что уже стояла у корня:

```powershell
icacls C:\Projects\agentic-openspec /setintegritylevel (OI)(CI)low /T /C
```

Итог: `919 files; Failed processing 0`. Запись проверена во всех подкаталогах, в `.git` и в
корневых файлах — везде `OK`. Подробности и откат — в `…-BLOCKER-sandbox-writes.md`.

**`NU1301` — та же причина, не сеть.** Сначала выглядел как SSL-проблема, но измерения показали:

| Условие | TLS к `api.nuget.org` | `dotnet restore` |
| - | - | - |
| Low IL (дочерний процесс песочницы) | `No credentials are available in the security package` | **NU1301** |
| Medium IL (расширенный режим) | OK, TLS 1.3 | **exit 0** |

Schannel не может взять ключи из хранилища при Low IL; TCP при этом соединяется. Значит nuget
доступен и **Батч 1 выполним**, но шаги `dotnet restore`/`build` требуют запуска с расширенным
доступом. Локально закэшировано не всё: `xunit.v3` и `nsubstitute` отсутствуют, сеть нужна.
