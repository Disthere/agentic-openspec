### Ручная часть — НУЖЕН ВЛАДЕЛЕЦ (5 минут)

По правилу плана батч 3 **не закрывается** без этого шага: именно его отсутствие и породило P0-9.
Выполнить в Web UI и записать результат:

1. Открыть DSH, переустановить профиль: `powershell -ExecutionPolicy Bypass -File .\dsh\install.ps1`.
2. Выбрать пресет **`sdd`** в селекторе пресетов.
3. Спросить: «перечисли доступные инструменты». Ожидание: `read`, `write`, `edit`, `pwsh`, `skill`, `todo`.
4. Попросить: «прочитай `.agents/analyst.md` и назови первый артефакт». Ожидание: чтение успешно.
5. Спросить: «какие значения `agent_preset` доступны». Ожидание: `sdd`.

> Без шага 3–5 батч остаётся **открытым** по критерию плана. Автоматика доказала композицию в
> `--dump-config`, но не доказала, что живая сессия её получает.

## Что не удалось и почему

**Задача 3.8 (read-only для QA и Reviewer).** В DSH 0.2.2-rc.1 нет permission-preset с
`sandbox: read-only` для сессии роли — конфигурации такого вида в дереве плагинов не существует.
План это предвидел (задача 3.10) и требовал **не выдавать дисциплинарное за техническое**; так и сделано:
в `reviewer.md` и `qa-engineer.md` прямо написано, что изоляция держится на дисциплине и обязательной
проверке `git status --porcelain`, а не на песочнице.

## Откат

`git revert` коммита. Профиль переустанавливается из `presets-bundle/`; резервные копии
`.bak-<timestamp>` создаются автоматически.
