## 0. Как запускать этот план

В наборе действует правило «ничего не делать до явной команды» ([`AGENTS.md`](AGENTS.md):7-8).
План активируется одной из команд (написать в чат главной сессии):

| Команда | Что выполняется | Оценка |
| - | - | - |
| `план: батч 0` | только фиксация базовой линии (безопасно, ничего не меняет) | 20 мин |
| `план: спринт 1` | батч 0 + 1 + 2 — **рекомендуемый минимум**: сборка зелёная, гейты машинные, цикл замкнут | 6–7 ч |
| `план: спринт 2` | батч 3 + 4 — роли DSH исполняются, канон и стандарты согласованы | 7–8 ч |
| `план: спринт 3` | батч 5 — шаблон готов к раздаче | 3 ч |
| `план: всё` | батчи 0–5 последовательно, с остановками на гейтах решения | 16–18 ч |
| `план: батч N` | один батч (N = 0…5) | см. таблицу батча |

**Правила исполнения плана:**

1. **Один батч — один коммит** (или серия мелких), после критерия выхода батча.
2. **Не переходить к следующему батчу, не выполнив проверку выхода.** Проверка — команда, а не суждение.
3. **Первое действие любой сессии — `git status`.** Сейчас в рабочем дереве 18 изменённых и 10+ неотслеживаемых
   путей; менять файлы поверх незакоммиченного состояния нельзя (диффы станут нечитаемы, ревью невозможно).
4. **Перед изменением — зафиксировать.** Требуется явное разрешение владельца на коммит (правило набора:
   не коммитить без команды). Если разрешения нет — работать в ветке `plan/remediation`, но батч не закрывать.

### Протокол старта сессии (скопировать в начало работы)

```text
1. Прочитай PLAN.md (этот файл) целиком.
2. Выполни «Батч 0» и покажи таблицу базовой линии.
3. Дождись команды на спринт/батч. Ничего не меняй до неё.
4. На каждом гейте решения (Раздел 3) спроси владельца, если ответ не зафиксирован.
5. После батча — покажи: что изменено (пути), вывод проверки, критерий выхода выполнен/нет.
```

## 1. Состояние на входе (базовая линия)

Зафиксировать и сохранить перед любыми изменениями — это «до», с которым сравнивается «после».

```powershell
# Батч 0 — выполнять ровно это, ничего не меняя
$stamp = Get-Date -Format 'yyyy-MM-dd-HHmm'
New-Item -ItemType Directory -Force -Path docs/baseline | Out-Null

git rev-parse HEAD                                    | Tee-Object docs/baseline/$stamp-git-head.txt
git status --porcelain                                | Tee-Object docs/baseline/$stamp-git-status.txt
dotnet --version                                      | Tee-Object docs/baseline/$stamp-dotnet.txt
dotnet --list-sdks                                    | Out-File -Append docs/baseline/$stamp-dotnet.txt

# Ожидаемые результаты «до» (это и есть доказательство дефектов):
dotnet build --configuration Release   2>&1 | Tee-Object docs/baseline/$stamp-build-before.txt   # MSB1003
dotnet test  --configuration Release   2>&1 | Out-File -Append docs/baseline/$stamp-build-before.txt
dotnet format --verify-no-changes      2>&1 | Out-File -Append docs/baseline/$stamp-build-before.txt

# DSH: композиция ролей «до»
$dsh = Join-Path $env:LOCALAPPDATA 'Programs\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd'
& $dsh --profile agentic-openspec --dump-config | Out-File docs/baseline/$stamp-dsh-before.txt
```

**Известный факт, который надо перепроверить в начале:** `--dump-config` для профиля в `$DSH_HOME`
может падать `EPERM` (profile-boot перезаписывает `cordis.yml`). Обход, проверенный ранее:

```powershell
$tmp = Join-Path $env:TEMP "dshplan-$stamp"
New-Item -ItemType Directory -Force -Path $tmp | Out-Null
$env:DSH_HOME = $tmp
powershell -ExecutionPolicy Bypass -File .\dsh\install.ps1 | Out-Null
& $dsh --profile agentic-openspec --dump-config    # exit 0, ~1428 строк
```

**Ожидаемое «до» для DSH (главный дефект P0-9):** у всех шести пресетов `preset-analyst` … `preset-ops-release`
секция `config.plugins` содержит **ровно один** элемент `@deepseek-ai/dsh-persona`.
Это и есть критерий «до»; после батча 3 их должно быть ≥ 8.

> ⚠️ `dotnet restore` в этом окружении иногда падает `NU1301` (транзиентный SSL к nuget.org).
> При проверке — повторить 2–3 раза, прежде чем считать провалом. Признак настоящей ошибки — `NU1202`/`NU1008`/`NU1010`.

## 2. Принципы этого плана

1. **Сначала то, что позволяет проверять остальное.** Машинный гейт (батч 2) важнее косметики: без него
   каждый следующий батч проверяется «на глаз».
2. **Одна причина — одно место.** Каждое правило/команда/список получает единственный источник; остальные
   места становятся ссылкой. Это лечит и P0-2, и 33 P2-находки о дублях.
3. **Проверка = команда.** Ни одна задача не закрывается словами «сделано». У каждой — `Проверка:`
   с исполняемой строкой и ожидаемым результатом.
4. **Deletion-first.** Где можно удалить, а не синхронизировать — удалять. Синхронизация двух копий
   уже провалилась в этом наборе трижды (персоны, команды гейта, стандарты).
5. **Не расширять объём.** План не добавляет новых ролей, стандартов, профилей. Только чинит существующее.

## 10. Инварианты — что нельзя сломать

1. **Конституция остаётся высшим приоритетом.** Любое изменение стандартов/DoD/схем — через предложение
   SDD (§5 для исключений), а не «правкой на ходу» (`.clinerules:154-165`).
2. **`openspec/proposals/archive/**` не редактируется**, кроме добавления (`.clinerules`, guardrails).
3. **Секреты не коммитятся.** `ROUTERAI_API_KEY` — только из окружения.
4. **`dotnet` CLI — единственный инструмент сборки.** Не вводить `msbuild`/IDE-шаги.
5. **Не добавлять новых ролей/стандартов/профилей.** План только чинит.
6. **Каждый батч оставляет репозиторий работоспособным.** Нельзя закрыть батч с красной сборкой
   или неработающим валидатором.
7. **`docs/legacy/` и контур ретрофита не трогать по содержанию** — это уникальная ценность набора;
   допустимо только сжатие `README.md` до шаблонов (4.30).

## 11. Риски и как их ловить

| Риск | Вероятность | Симптом | Мера |
| - | - | - | - |
| `dotnet restore` падает `NU1301` (SSL) | Средняя | не связан с изменениями; повтор проходит | Повторять 2–3 раза; отличать от `NU1202`/`NU1008`/`NU1010` |
| Композиция пресета адресуется не так, как ожидалось (вложенные id) | Средняя | `allowedAgentPresets` не применяется | Заменить `config.plugins` целиком или завести инстансы инструмента; проверить `--dump-config` |
| Живая проверка роли невозможна в headless | Средняя | нет UI | Проверить через `dsh --profile <p> --patch <overlay>` с пресетом, либо интерактивно в Web UI (ручной шаг владельца) |
| `install.ps1` затирает настройки при бэкапе | Низкая | `.bak` не создан | Бэкап **до** копирования; тест на копии профиля |
| CI не запускается (нет scope `workflow`) | Высокая | push отклонён | `gh auth refresh -h github.com -s workflow` (уже известно из SESSION-START) |
| Правки канона меняют поведение агентов | Средняя | агенты перестают следовать процедуре | Делать 4.1–4.4 одним коммитом, после — регресс-проверка: попросить агента пересказать правила |
| Юридический риск (P1-12) | Низкая | претензия | D-09: переписать `findings.md` самостоятельно |

## 12. Definition of Done всего плана

План считается выполненным, когда **все** утверждения проверяемы командами:

| # | Утверждение | Команда |
| - | - | - |
| 1 | Шаблон собирается с первого клона | `dotnet build -c Release && dotnet test -c Release && dotnet format --verify-no-changes` |
| 2 | Ни одно предложение не проходит мимо схемы | `tools/validate-proposals.ps1 -All` + негативный тест |
| 3 | Цикл SDD замкнут | `openspec/specs/**/spec.md` не пусто; `proposals/archive/` не пусто |
| 4 | Роли DSH исполняются | `check-dsh-profile.ps1` + ручная проверка владельца (§6 G3) |
| 5 | Делегирование по роли работает | вопрос модели «какие `agent_preset` доступны» → список |
| 6 | Канон = зеркало | `check-canon-parity.ps1` exit 0 |
| 7 | Шаблон раздаваем | `check-template-clean.ps1` exit 0 + прогон CLEANUP на копии за 10 мин |
| 8 | Ни одной «обещанной, но не работающей» автоматики | `MA0141`/`S103`/`GenerateDocumentationFile` включены; покрытие снимается |
| 9 | Метаданные не врут | README-дерево = `git ls-files`; GitHub description актуален |
| 10 | Аудит ASSESSMENT проходит повторно | повторный прогон проверок из ASSESSMENT §2 даёт 0 P0 и 0 P1 |

## 13. Что в план НЕ входит

- **Реализация продукта** (`src/` кроме smoke) — набор остаётся шаблоном.
- **Ревизия содержания 12 стандартов** — только согласование счётчиков и механики; сами стандарты
  не переписываются (это отдельные предложения SDD).
- **`csharp-desktop` стек** (Avalonia/LLamaSharp/ONNX/лицензии моделей) — только согласование
  конституции и схем; техническая проверка требует продукта.
- **Юридическая квалификация** P1-12 — решение владельца/юриста (D-09), план лишь предлагает безопасный путь.
- **Миграция на официальный bundle-механизм DSH** вместо `install.ps1` — кандидат в отдельное предложение
  после того, как роли заработают.
