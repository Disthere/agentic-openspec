# CHANGELOG-FROZEN — история изменений проекта до внедрения SDD

> **Приложение, не живой файл.** Чужой `CHANGELOG.md` не копируется сюда вслепую: сначала он
> **анализируется**. Актуальные записи (действующие версии, значимые изменения, на которые ссылаются
> документы) переносятся в проектный [`CHANGELOG.md`](../../CHANGELOG.md) как датированная история
> с указанием источника (`LEG-NNN`). Остальное переносится **сюда** — дословно, без правки формулировок
> и дат. Новые записи ведутся только в проектном `CHANGELOG.md` по
> [`04-documentation.md` §4.6](../../openspec/standards/04-documentation.md) с привязкой `(<ID>)`.

- **Дата среза:** `<YYYY-MM-DD>` — заполняется при первом применении процедуры в проекте; после этого
  файл не меняется.
- **Живой файл:** [`CHANGELOG.md`](../../CHANGELOG.md) — единственный действующий changelog проекта;
  актуальная часть истории перенесена туда.
- **Реестр:** [`docs/legacy/INDEX.md`](INDEX.md) — строка, по которой чужой changelog разобран.
- **Правила:** [`docs/legacy/README.md`](README.md), [`04-documentation.md` §4.10](../../openspec/standards/04-documentation.md).

## Правило ведения

1. Записи сюда **не добавляются**: с даты среза история пишется только в проектном `CHANGELOG.md`.
2. Сначала — **разбор**: каждая запись старого файла классифицируется как актуальная (идёт в проектный
   `CHANGELOG.md`) или историческая (остаётся здесь). Классификация фиксируется в строке реестра `LEG-NNN`.
3. Перенос сюда — **дословный**: формулировки, даты и порядок записей сохраняются; редактура при переносе
   запрещена. Перенос в проектный `CHANGELOG.md` — с указанием источника `LEG-NNN`.
4. **Ничего не теряется:** каждая запись старого файла доступна читателю — либо в проектном `CHANGELOG.md`,
   либо здесь, либо по исходному пути файла.
5. В проектном `CHANGELOG.md` остаётся одна строка-указатель на это приложение: место, где искать
   историю до даты среза.
