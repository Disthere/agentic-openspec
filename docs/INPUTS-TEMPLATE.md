# inputs/ — шаблон каталога входных материалов

> Скопируйте структуру в новый проект:
> ```
> inputs/
> ├── README.md      ← текст ниже (правила)
> ├── INDEX.md       ← реестр (см. ниже)
> ├── briefs/  concepts/  graphics/  samples/
> ```
> Правила ведения — [`openspec/standards/04-documentation.md` §4.9](../openspec/standards/04-documentation.md).

# inputs/ — входные материалы от заказчика (оператора)

Сюда складываются документы, которые **задают требования**: ТЗ, постановки, концепции, макеты,
образцы данных и форматов, референсы. Это **источник требований**, а не спецификация.

| Каталог | Что кладём |
| - | - |
| `briefs/` | ТЗ, постановки, требования, регламенты |
| `concepts/` | концепции, идеи, описания продукта, презентации |
| `graphics/` | макеты, скриншоты, схемы, примеры графики |
| `samples/` | образцы данных, выгрузки, фикстуры, форматы |

**Правила:** имя файла `IN-NNN-<slug>.<ext>` (номер сквозной); обязательная запись в `INDEX.md`;
ссылка из спецификации — раздел `## Sources` предложения; оригинал не правится; секреты и PII запрещены.

# INDEX — реестр входных материалов

| ID | Файл | Тип | Дата | Что задаёт | Статус | Где учтён |
| - | - | - | - | - | - | - |
| IN-001 | `briefs/IN-001-<slug>.pdf` | ТЗ | YYYY-MM-DD | <что определяет> | ⏳ не разобран | — |

Статусы: `⏳ не разобран` · `🔎 в разборе` · `✅ учтён (<NNN-slug>, D-NNN)` · `🗄 архив (не актуален)`.
