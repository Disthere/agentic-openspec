# Design — 005-adoption-guide

Почему инструкция выглядит именно так: один документ, промпты вместо шагов, одно ручное копирование.

## 1. Проблема

Развёртывание набора описано в трёх местах по-разному: [`README.md`](../../../README.md) (сценарии A/B
с таблицей «что копировать» и примерами команд), [`dsh/README.md`](../../../../dsh/README.md) (профиль),
[`docs/SESSION-START.md`](../../../../docs/SESSION-START.md) (состояние нашей сессии). Человеку приходится:
набирать команды, копировать пять-шесть каталогов, вручную сводить `.editorconfig` и `Directory.*.props`
и самому решать, что делать с конфликтами.

Требование владельца: интерфейс — промпты, ручной работы минимум, из файловых операций — копирование
**одной папки**.

## 2. Решения

| Решение | Почему так |
| - | - |
| Один документ `docs/ADOPTION.md` вместо правки трёх | человеку нужна одна точка входа; остальные ссылаются на неё |
| Промпты вместо шагов «сделайте X» | промпт — цельная инструкция агенту; человек не переводит инструкцию в действия руками |
| Ручных файловых операций ровно две, каждая — одна папка | (1) скопировать папку набора в проект; (2) скопировать папку материалов в `inputs/`. Всё остальное раскладывает сессия |
| Набор копируется **внутрь** проекта и удаляется после развёртывания | не нужен доступ к родительским каталогам и не остаётся второй копии набора, которая разъедется с первой |
| Слияние конфигов вместо перезаписи в промпте B1 | `.editorconfig`, `Directory.*.props`, `global.json` принадлежат продукту; их перезапись = тихая поломка сборки |
| Промпт B2 «опиши продукт как есть» | в проекте без SDD код уже есть, спецификации нет; без baseline любые изменения идут «поверх неизвестного» |
| Промпт B3 «оцени применимость стандартов» | иначе проект получит все правила сразу и застопорится на linting вместо продукта |
| Список человеческих действий + промпт проверки развёртывания | человек видит границу своей роли и понимает, когда развёртывание действительно закончено |

## 3. Что отклонено

| Вариант | Почему |
| - | - |
| Отдельная роль (пресет) `bootstrap` для развёртывания | роль без собственного гейта и повторяемой процедуры не нужна: пока это одноразовое действие, его делает главная сессия. Кандидат — `OQ-11`: вернуться, если процедура повторится |
| Скрипт установки (shell/PowerShell) в наборе | человек всё равно должен решить, куда и что ставить, а скрипт требует набора команд от него — прямо против требования |
| Копирование «пяти каталогов по таблице» (как в README сценарий B) | ровно то, от чего уходим: пять операций и пять решений вместо одной |
| Инструкция в `.agents/skills/` как скилл | скилл читает агент, а инструкция адресована человеку; смешивать роли нельзя |

## 4. Риски

| Риск | Митигация |
| - | - |
| Расхождение с `README.md` (сценарии A/B) | README ссылается на инструкцию как на единственную точку входа; сценарии A/B остались как справка |
| Ложное ожидание «агент сделает всё» | в инструкции явно перечислено, что делает человек, и есть промпт-жалоба, если работу перекладывают на него |
| Промпт в новом контексте без деталей | каждый промпт самодостаточен, заканчивается требованием отчёта и запретом лишних действий |
| Тихая перезапись конфигов чужого проекта | промпт B1 запрещает перезапись, требует слияния и отчёта «что слито» |
| Вторая копия набора в проекте | папка-источник удаляется на шаге 6 промпта B1 |
| Инструкция разъедется с продуктом (профили, роли) | инструкция не дублирует правила, а ссылается на `AGENTS.md`, `constitution.md` §7 и `.agents/README.md` |
