## Непроверенные условия

| Условие | Почему не проверено | Риск | План проверки |
| - | - | - | - |
| Процедура на реальном проекте с чужой документацией | нет второго проекта под рукой | высокий: реестр может оказаться громоздким, а шаги — непоследовательными | первый прогон B1a→B5→B6 на реальном проекте; по отчёту скорректировать промпты и формат реестра |
| Понятность промптов B1a/B5/B6 человеком без пояснений | машинно не проверяется | средний: формулировки могут требовать доработки | первый реальный прогон; уточнения — в раздел «Уточнения после приёмки» |
| Утверждение строк «партиями по 5–10» удобно владельцу | нужен живой владелец | средний: размер партии может быть неудобен | первый прогон; размер партии — параметр промпта |
| Выгрузка из реальной вики/Confluence (права, формат, объём) | нет доступа к внешней системе | средний: выгрузка может быть запрещена правами | на первом проекте с внешней вики: проверить сценарий R3 «указатель вместо выгрузки» |
| Проверка «ответ за один переход» на непустом репозитории | вопросы задаются по реальному проекту | средний: список из 10 вопросов может не покрыть специфику | первый прогон; вопросы дополняются по профилю проекта |
| Валидация схемы | CI разбора markdown-схемы не активен (`docs/ci/scaffold-check.yml` не подключён) | низкий: проверка выполнена вручную по тексту схемы | запуск CI после включения workflow |

## ИТОГ

- Предложение покрывает все подвопросы `OQ-14`: реестр и карта (R1), «источник истины один» (R2),
  внешняя документация (R3), архив и чужой changelog (R4), расхождения «документ vs код» (R5),
  проверка «ответ за один переход» (R6), обнаружимость и запись изменений (R7).
- Ключевые свойства процедуры: гейт «сначала только чтение, потом применение по утверждённым строкам»,
  запрет удаления, только промпты для Оркестратора, роль не вводится.
- Вердикт ревью: `VERDICT: Pass` — независимый проход Ревьюера выполнен отдельной сессией
  (read-only, отчёт в разделе «Выполненные проверки»); 8 находок, из них 7 `fixed` и 1 `rejected`.
- Утверждение человеком: **получено** — владелец, 2026-11-10, команда «утверждаю 006»
  (`Status: Approved`); решение зафиксировано как `D-008`…`D-014`.
- Реализация: задачи 2.1–5.4 выполнены (`tasks.md` — 15/15). Артефакты:
  `docs/legacy/` (README + INDEX + CHANGELOG-FROZEN), §4.10 в [`04-documentation.md`](../../../standards/04-documentation.md),
  шаги B1a/B5/B6 в [`docs/ADOPTION.md`](../../../../docs/ADOPTION.md) §3/§7, карты репозитория,
  `OQ-14` закрыт, `OQ-15`…`OQ-20` зарегистрированы, запись в [`CHANGELOG.md`](../../../../CHANGELOG.md).
- Финальная валидация (задача 5.4): разделы схемы 14/14; требования 7 = 7 и сценарии 16 = 16
  (proposal ↔ дельта, тексты совпадают); `tasks.md` — 15/15 по `item_pattern`; относительные ссылки
  во всех правленых файлах резолвятся (единственная битая — предсуществующая в `000-template.md`);
  23 блока-промпта в `docs/ADOPTION.md`, 0 терминальных команд вне промптов; гейт «утверждаю LEG-NNN»
  и запрет удаления в B5 на месте.

  [`specs/docs-alignment/spec.md`](./specs/docs-alignment/spec.md).
