# 09. Безопасность

## 9.1 Аутентификация и авторизация

- Аутентификация на границе (JWT Bearer / OIDC); токены валидируются (issuer, audience, срок).
- Авторизация — проверка прав на **каждом** защищённом эндпоинте (policy/role), для Minimal и controller API одинаково.
- Принцип наименьших привилегий для сервисных учёток и БД.

## 9.2 Секреты и конфигурация

- Секреты — только из окружения/vault; **никогда** в репозитории, образах и логах.
- Ротация секретов предусмотрена; строки подключения не логируются.

## 9.3 Ввод и зависимости

- Валидируй и нормализуй весь внешний ввод на границе (размеры, форматы, диапазоны).
- Защита от OWASP Top 10: инъекции (параметризованные запросы), SSRF, небезопасная десериализация, XSS на границах.
- Ограничивай размер запросов/тела, выставь rate limiting (`System.Threading.RateLimiting`).
- Зависимости — минимизированы, обновляются, без известных критических уязвимостей (аудит NuGet).

## 9.4 Данные и приватность

- Персональные данные (PII) — не логируются; маскируются в трассировке и сообщениях об ошибках.
- Шифрование в транспорте (TLS) обязательно; чувствительные поля — на стороне хранения по требованиям.

## 9.5 Запреты

- Секреты/токены/строки подключения в коде или конфигурации репозитория.
- Логирование PII, секретов, полных тел запросов с чувствительными данными.
- Открытые (незащищённые) административные эндпоинты.

## 9.6 В SDD

- Требования по правам доступа и угрозам фиксируются в спецификации (раздел доступа) и контрактах.
- Изменения модели безопасности — только через утверждённое предложение.
