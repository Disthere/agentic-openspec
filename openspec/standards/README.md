# Инженерные стандарты проекта

**Обязательно к прочтению** перед написанием любого кода или спецификации. Набор применяется ко всем
артефактам проекта: спецификациям, коду, тестам, документации, шаблонам и релизам.

Адаптировано под разработку **высоконагруженных ASP.NET-приложений и микросервисов** (.NET 8+/C# 12+).
Стандарты — детализация правил из [`AGENTS.md`](../../AGENTS.md) (канон для DSH) и [`.clinerules`](../../.clinerules)
(совместимое зеркало); источник истины для DoD и ревью.

## Как это связано с остальным

- [Конституция `openspec/constitution.md`](../constitution.md) — высший приоритет; стандарты ей подчиняются.
- [`.clinerules`](../../.clinerules) — совместимое зеркало кратких правил; канон для DSH — [`AGENTS.md`](../../AGENTS.md); стандарты — их полная детализация.
- [`.agents/`](../../.agents) — роли обязаны соблюдать стандарты; особенно [Ревьюер](../../.agents/reviewer.md),
  который берёт DoD как чек-лист приёмки.
- [`../schemas/csharp-api.yaml`](../schemas/csharp-api.yaml) — машиночитаемые гейты качества (покрытие, анализаторы, DoD).
- [`../project.md`](../project.md) — контекст проекта (стек, конвенции).

## Порядок работы со стандартами

1. **Архитектор** читает стандарты перед написанием спецификации и указывает в плане, какие правила затрагиваются.
2. **Разработчик** соблюдает стандарты при реализации и прогоняет гейт верификации.
3. **Ревьюер** сверяет код со стандартами и DoD из [`05-definition-of-done.md`](./05-definition-of-done.md).
4. Изменение любого стандарта = отдельное предложение SDD (Spec First), а не правка «на ходу».
