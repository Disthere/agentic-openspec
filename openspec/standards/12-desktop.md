# 12. Desktop (локальный продукт на устройстве)

Стандарт профиля **`csharp-desktop`** ([`openspec/config.yaml`](../config.yaml) → `project.profile`).
Применяется к десктопным продуктам: локальные модели, данные и ключи на устройстве, сеть — только
для обновлений. Микросервисный профиль `csharp-api` живёт отдельно: один проект выбирает **один** профиль.

## 12.1 Область

- Платформа: Windows (x64/arm64), .NET 10 / C# 14 (D-015); офлайн-сценарии — базовые, интернет не предполагается.
- Продукт обязан работать **без интернета**: доступность сети не является условием основной функции.
- Всё, что уходит за пределы устройства, — исключение, оформленное по конституции §5, и перечисленное в §12.6.

## 12.2 Слои и границы

| Слой | Технология | Правило |
| - | - | - |
| UI | **Avalonia 11+** + **CommunityToolkit.Mvvm** | MVVM, `View` не содержит логики; только `ViewModel` знает о ядре |
| Ядро (домен) | чистый C# | **не ссылается** ни на UI-типы, ни на типы конкретного рантайма моделей — только на интерфейсы |
| Инфраструктура | рантайм моделей, хранилище, крипто | реализует интерфейсы ядра; единственный слой, знающий про сторонние SDK |

- Внутренняя связь слоёв и компонентов — **in-process шина (Channels)** и **named pipes** для отдельных
  процессов. **HTTP-портов, loopback-серверов и «локального API по сети» нет.**
- Сторонние SDK подключаются через интерфейсы ядра: замена runtime (LLamaSharp → ONNX Runtime GenAI)
  не должна задевать домен.
- Асинхронный UI: ни один вызов инференса не блокирует поток интерфейса; отмена — через `CancellationToken`.

## 12.3 Локальный рантайм моделей

| Задача | Решение | Замечания |
| - | - | - |
| LLM | **llama.cpp через LLamaSharp**, формат **GGUF** | версия пакета **фиксируется** (`Directory.Packages.props`), апгрейд — отдельным предложением с замером |
| Альтернатива LLM | ONNX Runtime GenAI (DirectML) | применяется на Lite-тире; один бэкенд для NVIDIA/AMD/Intel |
| STT | GigaAM / Whisper (small, turbo) | приоритет русского языка |
| TTS | sherpa-onnx (Piper / VITS) | **без GPL-голосов и без NC-лицензий** |
| VAD | Silero VAD (ONNX, MIT) | лёгкий, русскоязычный |
| Vision/OCR | ONNX Runtime: PaddleOCR, Florence-2, CLIP/SigLIP | лицензии Apache-2.0/MIT |

- Модели **не хранятся в репозитории**: в репозитории — манифест (имя, размер, хэш, лицензия), сам файл
  пользователь скачивает по явному действию (см. §12.6).
- У каждой модели в манифесте — лицензия и требование к железу (RAM/VRAM, CPU-инструкции).
- Скачивание и проверка хэша — часть продукта, а не «ручная инструкция».

## 12.4 Хранилище и ключи

- Локальная БД — **SQLite**; векторный поиск — **sqlite-vec**; шифрование БД — **SQLCipher**.
  Один файл на профиль пользователя, порт не открывается.
- Ключ БД и прочие секреты — в **Windows DPAPI / Credential Locker**; в конфигах и логах их нет.
- Восстановление доступа — **seed-фраза BIP39 (24 слова, 256 бит)**; UI обязан предупредить о потере
  данных при утрате фразы и не хранить её копию в открытом виде.
- Облачной синхронизации по умолчанию нет: экспорт/импорт — только явным действием пользователя.
- Миграции схемы — версионируются и проверяются на обратимость (см. [`07-persistence.md`](./07-persistence.md) §7.1).

## 12.5 Криптография

- Только `System.Security.Cryptography`: **AES-256-GCM** (данные), **HKDF** (вывод ключей),
  **Ed25519** (подписи манифестов обновлений). Никаких самописных примитивов.
- Nonce/IV уникален для каждой операции; ключи не логируются и не попадают в телеметрию (её нет).
- Секреты не коммитятся; `.env`, `*.pfx`, хранилища ключей — вне репозитория (см. `.gitignore`).

## 12.6 Сеть: одна дверь наружу

- **Единственная точка выхода** — gateway обновлений: проверка **подписанного манифеста** (Ed25519),
  загрузка пакета, применение через установщик (§12.7). Никаких портов и фоновых соединений.
- Загрузка моделей — по явному действию пользователя, с показом источника, размера и хэша.
- **Аналитика отсутствует** (принцип «нет телеметрии»): ни метрик, ни «краш-репортов по умолчанию»,
  ни сетевых SDK. Любая новая сетевая возможность — отдельное предложение + исключение по конституции §5.
## 12.7 Упаковка и обновления

- Установщик: **Velopack** (основной путь) / **Inno Setup** (офлайн-вариант). Установка — **без прав
  администратора**; деинсталляция чистая (пользовательские данные удаляются только по согласию).
- Обновления: дельта-пакеты через gateway (§12.6), **обязательна проверка подписи манифеста**;
  предусмотрен путь возврата на предыдущую версию, описанный в runbook релиза.
- Версии — SemVer; для пользователя — человекочитаемый changelog («что изменилось в поведении»),
  техническая запись — в `CHANGELOG.md` продукта по [`04-documentation.md`](./04-documentation.md) §4.6.

## 12.8 Бюджеты ресурсов вместо серверных SLO

| Метрика | Как измеряется | Цель |
| - | - | - |
| Холодный старт приложения | секундомер до готового окна, эталонное железо | фиксируется после первого замера (`OQ-10`) |
| Загрузка модели в память | время до первого запроса к модели | `OQ-10` |
| Idle RAM (без сессии) | диспетчер задач / PerfView, 5 минут простоя | `OQ-10` |
| Пиковая RAM при инференсе | PerfView / dotnet-counters | `OQ-10` |
| Latency первого токена, токенов/с | замер на фиксированном промпте, CPU-only и GPU | `OQ-10` |
| Отклик UI во время инференса | отсутствие пропущенных кадров/залипаний, ручной сценарий | UI не блокируется |
| Размер установщика и модели по умолчанию | размер файлов в релизном артефакте | `OQ-10` |

Правила: бюджеты измеряются на **зафиксированном эталонном железе** (указывается в `performance.md`);
числовые цели не выдумываются — до первого замера фиксируется «метрика + способ замера»; заявление
о производительности без замера недействительно ([`11-performance.md`](./11-performance.md) §11.3).

## 12.9 Доказуемость приватности

Приватность подтверждается **тестами и анализаторами**, а не заявлениями:

1. **NetArchTest** — правила зависимостей: ядро не зависит от сетевых сборок; типы `System.Net.*`
   допустимы только в сборке Gateway; UI не обращается к инфраструктуре напрямую.
2. **Roslyn-анализатор** — запрет использования `HttpClient`, `System.Net.Sockets`, `WebClient`
   вне проекта `*.Gateway` (сборка падает, а не предупреждает).
3. **Тест «нулевой egress»** — прогон основных сценариев при заблокированной сети; результат
   фиксируется в `acceptance.md` как улика.
4. **Проверка отсутствия телеметрии** — в сценарии нет сетевых вызовов; в зависимостях нет SDK аналитики.

## 12.10 Лицензионный инвентарь

- Обязательный артефакт продукта — **инвентарь лицензий** (`licenses.md`): компонент, версия, лицензия,
  режим использования, обязательства (атрибуция, share-alike, ограничения).
- В поставляемом бандле **запрещены GPL/AGPL и NC-лицензии**; голоса TTS — только с разрешёнными лицензиями.
- Лицензия каждой модели фиксируется в манифесте моделей; несовместимая модель в поставку не попадает.
- Проверка инвентаря — обязательный пункт релизного гейта (§5.8 DoD).

## 12.11 Тесты

- Фреймворк — xUnit + FluentAssertions/NSubstitute ([`.clinerules`](../../.clinerules), стандарт 01).
- **Архитектурные тесты (§12.9) — часть обязательного прогона**, а не «опциональный контроль».
- Изоляция: тесты не пишут в пользовательский профиль — только временный каталог.
- Инференс в юнит-тестах — детерминированная заглушка или крошечная модель; прогоны на реальных моделях —
  отдельный, помеченный набор, не входящий в быстрый цикл.
- Логика MVVM тестируется без UI; UI-тесты — по возможности headless.

## 12.12 Горячие пути (инференс, кадры UI)

- Без LINQ и лишних аллокаций; `Span`/`ArrayPool`/`ValueTask`; никогда `.Result`/`.Wait()`.
- Поток токенов обрабатывается стримингом: не собирать весь ответ в память ради UI.
- Файловые и сетевые операции — асинхронно, с `CancellationToken`; отмена — часть UX, а не «потом».
