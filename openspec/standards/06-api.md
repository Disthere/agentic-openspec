# 06. API и контракты

Применяется к HTTP/REST и gRPC API сервисов.

## 6.1 Дизайн

- Ресурсные маршруты, корректные HTTP-методы и **коды состояния**: `200/201/202/204`, `400/401/403/404/409/412/422`, `429`, `500/503`.
- **Ошибки — единообразно** через `ProblemDetails` (**RFC 9457**): `type`, `title`, `status`, `detail`, `instance`, расширения (`traceId`, `errors`). Никаких «утечек» stack trace.
- **Валидация** на границе (DataAnnotations + FluentValidation); ответ валидации — `422` c перечнем полей.
- **Пагинация/фильтрация/сортировка** для коллекций: `page`/`pageSize` (или курсор), сортировка по whitelist, лимит размера страницы.
- **Идемпотентность** изменяющих операций: заголовок `Idempotency-Key`; повтор с тем же ключом возвращает тот же результат.
- **Таймауты и отмена**: `CancellationToken` в каждом эндпоинте; внешние вызовы — с таймаутом.

## 6.2 Версионирование и совместимость

- Версия API — явно (`/v1/...` или заголовок), через `Asp.Versioning`.
- **Совместимые изменения** — можно (добавление необязательных полей/эндпоинтов).
- **Ломающие изменения** — только через конституцию (раздел 4): новый план, миграция, период совместимости.
- OpenAPI генерируется автоматически (`Microsoft.AspNetCore.OpenApi`), документация эндпоинтов обязательна (в т.ч. Minimal APIs).
- Транспорт: **REST/JSON** — для внешних контрактов; **gRPC/Protobuf** — для внутренних (`Grpc.AspNetCore`, `Grpc.Tools`).

## 6.3 Контракты в SDD

- HTTP- и событийные контракты фиксируются в `<предложение>/contracts/` (см. шаблон [`../../openspec/proposals/000-contracts/README.md`](../../openspec/proposals/000-contracts/README.md)).
- Изменение контракта = изменение спецификации = ревью.
- Внутренние вызовы сервисов покрываются **consumer-driven contract-тестами**.

## 6.4 Запреты

- `200 OK` с телом-ошибкой; «swallowed» ошибки; коды, не соответствующие семантике.
- Breaking change без версии и миграции.
- Возврат сущностей БД напрямую — только DTO/модели контракта.
